# Approval_Store golden vectors

Data files for the PowerShell writer (task 4.10) and the TypeScript reader (task 1.16). Both must agree with them.
Generated by `src/approval/vectors.ts` (`node dist/tools/generateApprovalVectors.js <dir>` inside the toolchain container);
a unit test fails if these files differ from what the generator produces. Do not edit by hand.

- `valid-chains.json`: records with `hashInput` (canonical JSON without `hash`), `hashInputHex` (its UTF-8 bytes), `hash` (SHA-256, lowercase hex) and `line` (stored form without the LF). `storeText` is the whole file.
- `candidate-validation.json`: candidates against a context store; `expectedFields` is written by hand (empty = accepted). Rejection must leave the store byte-identical and name each field.
- `tamper-cases.json`: store texts with hand-written findings (`modified`, `missing`, `chain_break`, and `supersedes` rule violations). Tail truncation is detected only with an `anchor`.

Canonical form: keys sorted by UTF-16 code unit, no whitespace, UTF-8 without BOM, shortest string escapes (`\"`, `\\`, `\b \t \n \f \r`, other controls below U+0020 as `\u00xx` lowercase, DEL and non-ASCII written raw), one LF after each line.

Security note: the chain is tamper detection only. Write control comes from OS/container permissions (the runtime has no mount), and `recorded_by` is a declaration that the chain cannot authenticate.
